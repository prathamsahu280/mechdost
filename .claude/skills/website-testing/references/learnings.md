- T23 · 2026-11-01 · gates · `pnpm format:check` failed once because a background research agent was mid-write on a new doc; rerun passed. → If format:check fails on a file a background agent owns, wait for the agent or rerun; never "fix" a file another agent is writing.
- T24 · 2026-11-01 · maps · New map controls (Map/Satellite toggle) need e2e on `aria-pressed`, pins surviving `setStyle` (markers are DOM, layers are not) and the saved mode in localStorage. Added to the workshop map test in demo-flows.spec.ts.
- T25 · 2026-11-01 · fixtures · (promoted to the advisor checklist 2026-11-03 after a third occurrence) Order codes use Crockford base32 (no I, L, O, U): fixtures like "LIVE…"/"RELA…" fail the CHECK. → Build test codes from `0123456789ABCDEFGHJKMNPQRSTVWXYZ`.
- T26 · 2026-11-01 · typing · Drizzle `.set({ unknownColumn })` compiled away at runtime in a test (vitest passed) but `tsc` caught it. → Always run `tsc` on test files too (they are in the package tsconfig) before trusting a green vitest.
- T27 · 2026-11-02 · i18n · User found English on `/hi/workshops`: workshop names, areas, service names and OSM map labels came from English-only demo data and tiles, which the key-based i18n tests never see. → Hindi coverage is checked on rendered pages, not just locale files: `e2e/hindi-coverage.spec.ts` crawls every `/hi` route (incl. dynamic product/workshop pages and portals) and fails on Latin-script words outside the allowlist (brands, units, codes, user-written text). - T28 · 2026-11-02 · state bugs · "Doesn't always happen" map bug = state-dependent (a workshop selected before locating). → For every interactive widget, test action sequences across states (select → locate ×3, select → show all → select), assert camera/visibility, and assert DOM identity (no rebuild) and no page scroll. Measure scroll AFTER `scrollIntoViewIfNeeded` (Playwright scrolls before clicking).
- T29 · 2026-11-02 · i18n gate · The first render-gate run on `/hi` passed every signed-in page while they showed empty states, and it found English nobody had listed: the footer's legal name/address (from `lib/site.ts`), inline strings ("MechDost Partner", "Raipur"), a client component reading a namespace its page never sent (`cities.raipur` printed as a key), MapLibre's built-in English labels ("Close popup", "Map marker"). → A language gate must (1) seed records and assert each page shows one (`MUST_SHOW`) before judging it, (2) read `aria-label`/`placeholder`/`title`/`alt`/`<option>` text and `document.title`, not just body text, (3) pass every third-party UI string through our locale files (MapLibre `locale` option).
- T30 · 2026-11-03 · next/rsc · A Server Component imported a value (`WHATSAPP_EVENTS`) from a `'use client'` module; typecheck and lint passed, but the build's prerender crashed ("map is not a function") because client-module exports are references on the server. → Server code imports values only from shared/non-client modules; `next build` is part of verification for any server-component change.
- T31 · 2026-11-03 · next/navigation · A client component read `?order=` from `window.location` during render; after a `<Link>` navigation Next renders the new page before updating the address bar, so the preset was empty (caught by e2e on both projects). → Read query params with `useSearchParams()` (wrap in `<Suspense>` on statically built pages), never `window.location` in render.
- T32 · 2026-11-03 · tooling · `playwright test -g "/support"` found no tests: Git Bash (MSYS) rewrote the leading-slash argument into a Windows path. → Use patterns without a leading `/` (e.g. `"(admin|account).support"`) or set `MSYS_NO_PATHCONV=1`.
- T33 · 2026-11-03 · tooling · Stopping a backgrounded `pnpm exec next start` task killed the pnpm wrapper but left the `next` node process serving; after a rebuild it 404'd the new routes. → Before restarting the demo, check who owns the port (`Get-NetTCPConnection -LocalPort 3000`) and stop that process; verify new routes return 200 after the restart.
- T34 · 2026-11-03 · speed/flake · Each DB/API test file created a PGlite and ran all 24 migrations; under memory pressure a setup hook hit 120 s and a whole file failed. → Vitest `globalSetup` builds one migrated template per run (`buildTestDbTemplate`, temp file keyed by a hash of the migrations) and `createTestDb()` loads a copy (`loadDataDir`). DB suite 100 tests in 78 s, API 57 in 48 s.
- T35 · 2026-11-03 · data · Price-resolution tests must make the cheapest offer _not_ the expected one (a farther cheaper shop, a paused cheapest shop, a busy nearest shop, an empty shelf), otherwise "lowest" and "nearest" pass the same test. Keyset pagination tests insert a newer row between pages and assert no duplicate/skip; cursor tests include a forged payload (SQL text, bad uuid) → 422.
- T36 · 2026-11-03 · flake · `crypto.test.ts` "tampering" replaced the first ciphertext character with a fixed `A`; with random IVs the ciphertext already started with `A` about 1 run in 64, so nothing was tampered and the test failed (the gate held the commit). → A mutation in a test must be guaranteed to change the value (pick a different character than the current one, or XOR a byte); assert the mutated value differs.
- T37 · 2026-11-03 · fixture · An "expired block" fixture set `ends_at = created_at + 1 s` and `created_at = now() - 1 day` in one UPDATE; SQL SET reads the _old_ row, so `ends_at` landed one second in the future and the block was still active. → When back-dating rows, compute every timestamp from `now()` directly, never from another column changed in the same UPDATE.
- T38 · 2026-11-03 · fixture · Second time in a day (T37): back-dating `order_assignments.expires_at` alone broke CHECK `expiry_after_offer`. → **Promote:** any timestamp fixture that moves one end of a constrained pair moves both, computed from `now()`. Constraint failures in fixtures are the schema working, not flakiness.
- T39 · 2026-11-03 · overlays · Adding a fixed consent banner: the click-every-button audit reopened it via "Privacy choices" and then could not click the floating "Ask MechDost" button it covered on mobile (5 failures). A real stacked-overlay bug, not test noise. → Any new fixed/floating UI: (a) e2e suites start from a storage state where it is dismissed (`e2e/fixtures/consent-decided.json` in the config `use`, and in every `browser.newContext`), (b) a dedicated spec starts clean, (c) two floating elements never overlap — the lower-priority one steps aside (`html[data-consent-open] .assistant-launcher`).
- T40 · 2026-11-03 · flake · roles.spec "wrong details get one generic message" failed once on mobile: after a second wrong sign-in it waited for the error text, which was already visible from the first attempt, so it typed the next email while the (slow, hashed) attempt was still running and the late result overwrote the field. → After repeating an action whose feedback is already on screen, wait for the action itself to finish (button enabled again / busy state cleared), never for the stale message.
- T41 · 2026-11-03 · e2e/build · After changing demo select options, roles.spec timed out with "did not find some options": Playwright's webServer is `next start` on the existing `.next` output, so e2e ran the previous build. → Run `pnpm --filter @mechdost/web exec next build` before any e2e run that follows a web source change; a "missing option/text that the source clearly has" failure means a stale build first.

- T43 · 2026-11-03 · ci · The first CI run failed while every local run passed: web lint needs the types `next typegen` writes (next-env.d.ts, .next/types for next/root-params and image imports); locally they were left over from builds, in CI lint ran before typecheck generated them. → Any task that reads generated files generates them itself (web lint = `next typegen && eslint`). - T45 · 2026-11-09 · a11y/announcements · The sign-in errors used a conditionally mounted role=alert next to the field: VoiceOver often misses it and nobody hears a repeated identical error; a disabled busy button dropped focus to <body>; a countdown sat in aria-live.
