## Architecture

- `packages/shared/src/email-templates.ts`: registry (purpose, category, audience, closed placeholder list, en + hi
  default copy `{subject, heading, body, button}`, button path), `composeEmail` (override merge, placeholder fill),
  `emailOverrideProblem` (unknown placeholder, length), `sampleParams` for previews.
- `packages/shared/src/email-layout.ts`: fixed MechDost layout, table-based, inline styles, dark-mode safe; HTML + text;
  footer company, support phone, grievance contact shown only when set.
- `packages/shared/src/email-phrases.ts`: localized phrases computed at queue time (reasons, refund notes, methods).
- DB: migration `email_templates` adds nullable `heading`, `button_label` to `notification_templates`.
  Email rows: channel `email`, no row = default text and on; `body = ''` = no body override; row `enabled=false` = off.
- `packages/db/src/repo/email-notifications.ts`: `queueEmail` (single writer: enabled check, recipient resolution with
  verified-only setting, language, dedupe `{template}:{entity}:v{version}:email`), per-domain helpers called inside the
  repos that change state, plus the exported refund helper `queueRefundEmail`.
- `notification-admin.ts`: email override save/reset/toggle (audited, compare-and-set), list.
- API: `GET/PUT /admin/notifications/emails`, `POST .../emails/{key}/reset`, `POST .../emails/{key}/test`
  (test send = outbox row to the staff member's own email, same pipeline).
- Adapter: `loadOverride` hook; `email_sent` / `email_failed` server events from the dispatcher (no addresses).
- Web: Admin -> Notifications gets an Emails tab (`admin-emails-api.tsx`), real sign-in mode only.
