Design: `docs/superpowers/specs/2026-11-15-bell-push-design.md` (binding). Spec: 10. Runbook: `docs/runbooks/push.md`. Branch `worktree-agent-a9d34f0d3fda674f2`. Every task: test first, then code, then the matching doc line in the same change.

## Advisor brief (key lines)

- **Conflicts and corrections:** (1) the design says "bell updates through the existing live pings", but no browser live client exists yet (spec 10: "the next step"), so the bell polls and a push wakes open tabs; recorded as a decision. (2) the design lists the VAPID key only, the web SDK also needs the Sender ID: new public variable, Q103 widened. (3) `notifications` needs a `dedupe_key` (rule 3), not in the design's column list. (4) a `firebase` umbrella install would reintroduce the 2026-11-09 grpc advisory: use `@firebase/messaging` only.
- **Risks:** (a) JS budget: the Firebase library must stay out of every page view (proof by import-graph test). (b) lock-screen privacy: payload is title, short body and link, placeholders closed per kind. (c) duplicate or lost notices around state changes: written in the business transaction, deduped per person.
- **Applicable learnings:** L100 (locale keys by text insertion, own namespaces; API-mode screens in `*-api.tsx` loaded dynamically), L123 (every byte in always-loaded islands counts), L141 (worker interval bodies catch their own errors), L144/L148 (edit tools instead of heredocs in the worktree), L147 (migration numbering), L152 (grep the schema before planning a migration), L153 (text with data needs the recipient's language inside the transaction), L145 (real-mode views go in `REAL_MODE_VIEWS`).
- **Skills:** mechdost-advisor, writing-plans, test-driven-development, notifications-messaging, serwist-pwa (decision: no PWA; plain worker), firebase-phone-auth-rbac, drizzle-postgis-supabase + supabase-postgres-best-practices, domain-modeling, hono, vercel-react-best-practices + core-web-vitals, ui-ux-pro-max, shadcn-component-discovery, frontend-design, shadcn-component-review + web-design-guidelines + accessibility, next-intl-hindi, website-testing, verification-before-completion.

## Tasks

1. **Schema** (`packages/db/src/schema/platform.ts`, migration `0057_notice_push`): `notifications` + category, kind, entity_type, entity_id, dedupe_key, CHECKs, unique partial index, created_at index; `push_devices` (RLS on, anon/authenticated revoked). Test: `schema-invariants` (RLS on every table).
2. **Catalogue and DTOs** (`packages/shared`): `notice-catalogue.ts` (33 kinds, closed placeholders, link builders, `composeNotice`, override checks), `notice-api.ts` (strict DTOs, limits), default texts under `notify.*` and UI under `bell.*`, `adminNotices.*` in en and hi, four settings, analytics events. Test: `notice-catalogue.test.ts` (language, length, placeholders, no PII placeholders, local links, email mapping).
3. **Writer and hooks** (`packages/db/src/repo/notices.ts`, `notice-events.ts`): `queueNotice` (language, overrides, preference, device, consent, cap, dedupe), `queueStaffNotice` (permission + city), hooks in `queueEmail`, `declineAssignment`, `expireAssignment`, `notifyStaffShopGaveUp`, `queueOrderPlacedEmail`, application and ticket creation. Tests: `notices.test.ts`.
4. **Lists, preferences, devices, jobs** (same repo file): keyset list, unread count (bounded), mark read (own ids), preferences + consent log, register/revoke devices, offer-expiry reminders, refund-SLA alerts, retention.
5. **API** (`apps/api/src/routes/notices.ts`, admin routes in `admin-notifications.ts`, `notice-templates-admin.ts`): the routes in spec 10, rate limits, strict bodies; generic template endpoint refuses `inapp`/`push`. Tests: `apps/api/test/notices.test.ts`.
6. **Push adapter and worker** (`apps/api/src/notify/push.ts`, `worker.ts`, `dispatcher.ts` events): FCM `sendEach`, revoke gone tokens, back-off classes; reminder, SLA and retention timers. Tests: adapter cases in `notices.test.ts` (fake transport; never a real send).
7. **Web: library and worker** (`lib/push/*`, `lib/notices-api.ts`, `public/firebase-messaging-sw.js`, CSP, headers, sign-out hook, `@firebase/messaging` 0.13.3). Test: `push-lazy.test.ts`, `notices-view.test.ts`, `csp.test.ts`.
8. **Web: UI** (`components/notices/*`, header, `/notifications`, Account → Notifications, portal prompt slots, admin Messages tab, shop offers and admin queue refetch). Review pass: accessibility (live region, focus return, 44 px targets, `New` tag not colour alone), Hindi, long titles, three audit widths in the state-audit model (`REAL_MODE_VIEWS`).
9. **Config and docs**: `.env.example`, `deploy/env.server.example`, Dockerfile, CI and deploy build args; spec 10, 12, 14, 16, decisions, progress, runbook, security research, UI test catalogue, learnings (advisor and website-testing).
10. **Verification**: targeted tests while building; `pnpm check` once at the end (must pass fully); no Playwright, no `next build`, no real push or email.
