# Coupons implementation plan (2026-11-15)

Design: `docs/superpowers/specs/2026-11-15-catalogue-storefront-next-tier-design.md` item 2 + decisions "Next tier answers" and "Coupons built". Order of work (test first where it holds money):

1. **Pure maths** `packages/shared/src/coupon.ts`: kinds, funders, reason codes, `applyCoupon`, `allocateLargestRemainder`, IST helpers. Tests first (fast-check properties: sums, bounds, caps, eligibility).
2. **Schema + migration `0064_coupons`**: extend `coupons`, add `coupon_shop_terms`, `coupon_user_usage` (+ trigger limit), `coupon_redemptions.funder/released_at`, order group/sub-order/line columns and CHECKs, `coupon_discount` payout kind. RLS on new tables.
3. **Repos**: `coupons.ts` (evaluate, redeem by conditional UPDATE, release, payout entry), `checkout.ts` (price path: coupon, coins on net, COD cap, snapshot, allocation), `checkout-coupon.ts` (preview), `coupons-admin.ts`, `coupons-shop.ts`; `orders.ts` hooks on cancel/reject/deliver.
4. **DB tests** (`packages/db/test/coupons.test.ts`): pricing + snapshot + allocation, coins after coupon, COD cap, replay, quote refusal, every refusal reason, DB rules, parallel last use, release (all parts vs one part), payouts (MechDost, shop, rerouted), shop acceptance (pending, re-ask, stale, role leak), admin CRUD/scope/audit/cursor.
5. **API**: `routes/coupons.ts` (customer check, admin, shop offers), `couponCode` on `POST /orders`; role-leak and rate-limit tests.
6. **Web** (lazy, no always-loaded code): checkout field, admin Coupons section, shop offers card, view helpers + tests; locale namespace `coupons` (en + hi).
7. **Docs, state-audit rows, learnings**; targeted lint/typecheck/prettier only (the coordinator runs the full gate at merge).
