# 13 · RBAC, security & abuse protection

Status: decided · Phase 1 · Decisions: Staff security, Non-functional requirements; research `../research/security-vulnerabilities.md` (recent CVEs, written after research completes)

## RBAC

- Permissions are `resource:action` strings (orders:read, orders:route, orders:refund, refunds:approve, products:publish, partners:approve, content:publish, settings:write, customers:impersonate, …) stored in `permissions`; roles in `roles` with `role_permissions`; `user_roles` with optional `city_id` and `partner_id` scope. Firebase custom claims carry role ids + partner_id; the API resolves effective permissions per request (per-instance cache 60 s keyed by the sign-in time, so every new sign-in loads fresh; invalidated locally on change).
- Default roles and matrix: see `../research/ecommerce-baseline.md` §7 (super_admin, ops_manager, support_agent, finance, catalogue_manager, city_manager, marketing, seller_owner, seller_staff, workshop_owner, workshop_staff, mechanic, customer, guest).
- Enforcement: Hono middleware `requirePermission()` + repository-level scoping (`actor`), RLS mirror in Supabase (defence in depth); live pings in Firebase RTDB carry opaque ids only and each user can read only `/inbox/{uid}` (rule `auth.uid === $uid`), the worker decides recipients from Postgres, data always refetched through the API; UI hides what the actor cannot do; 404 for cross-tenant ids.
- Four-eyes: refunds/manual coin grants/payouts/commission changes above `settings.approval_threshold_paise` require requester ≠ approver.
- Staff 2FA (TOTP) implemented; enforced automatically once any staff beyond founders exists (`settings.enforce_staff_2fa` auto-true on 2nd staff).
- **CSP (2026-11-09):** site-wide allow-list policy from `apps/web/src/lib/csp.ts` (decisions 2026-11-09); and in real sign-in mode a nonce + `strict-dynamic` policy on `/login` (proxy `src/proxy.ts`, layout inline scripts by hash).
- Staff sign-in = password + a phone code every time (decision 2026-11-01); the API grants staff permissions only to a session made by both steps (`staff_2fa` custom-token claim, ≤ 12 h old), otherwise `STAFF_2FA_REQUIRED` (built 2026-11-09, spec 01).
- Sessions: staff idle 30 min / absolute 12 h; partners 7 days; customers 30 days; sign-out-all; new-device alert (P1).
- Audit log on every mutation (actor, ip, entity, before/after, reason) — immutable.

## Encryption (decision 2026-11-01, user: "the passwords and database need to be properly encrypted")

| Layer       | What                                                                                                                                                                                                                                     | Where                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| Passwords   | Never stored by us; Firebase Auth hashes them (scrypt). Demo: PBKDF2-SHA-256 + salt.                                                                                                                                                     | spec 01                     |
| In transit  | TLS on every non-local DB connection (`tlsFor`): verify-full with `DATABASE_CA_CERT`, **mandatory in production** (the API refuses to start without it, so no MITM downgrade); dev may use `require` until Q23; HTTPS + HSTS for web/API | `packages/db/src/client.ts` |
| At rest     | Supabase AES-256 disk + backup encryption; PITR backups encrypted                                                                                                                                                                        | Supabase                    |
| Field level | AES-256-GCM envelope `v1.<keyId>.<iv>.<ct>.<tag>`, column name as AAD, random IV; blind index (HMAC-SHA-256) for lookups                                                                                                                 | `packages/db/src/crypto.ts` |
| DB guard    | CHECK constraints: `*_enc` columns accept only envelopes → plain text is rejected by Postgres (23514)                                                                                                                                    | migrations 0004–0005        |

Encrypted columns: `shops.pan_enc` (+ unique `pan_index`), `partner_applications.kyc_enc` (PAN, GSTIN, bank/UPI for payouts as JSON), `refunds.destination_enc` (required when `mode = 'bank_upi'`), `staff_security.totp_secret_enc`. Any new column holding government IDs, bank/UPI details, documents' numbers or secrets **must** be `*_enc` + `encryptedCheck` (checklist item). Keys: `DATA_ENCRYPTION_KEYS` (`id:base64,…`), `DATA_ENCRYPTION_KEY_ID`, `DATA_INDEX_KEY` — Secret Manager in production, never in git; rotation = add a key id, switch the current id, re-encrypt with `needsRotation` in a job, then retire the old key. Plain (for lookups): phone, email, names, addresses — protected by RLS, least privilege, PII masking for support, audit logs that record field names only. Tests: `packages/db/test/crypto.test.ts` (round trip, tamper, wrong column, rotation, config), `integrity.test.ts` "encryption at the database boundary", `tls.test.ts`.

**Logging (2026-11-03):** error logs carry `safeError(err)` only (error class, Postgres SQLSTATE, stack frames) plus ids and codes; never `err.message`/`err.stack`, which for database errors contain the query parameters (phones, message text). Jobs count failures outside the failed transaction and park poison items after 5 attempts with an error code.

## Seller onboarding (2026-11-13)

- **Permissions:** `prices:approve` (new, in the ops roles) decides price requests; `partners:approve` approves or rejects applications and creates invites; `partners:write` lists and revokes invites; `content:write` publishes agreement versions. Shop routes need the shop's owner or staff (another shop → 404).
- **Abuse:** the public application and invite routes need Turnstile; 5 applications and 30 invite opens per IP per hour, and 3 applications per mobile number per day (keyed by a hash of the number); the location search allows 10 searches a minute per client and never searches as you type (Nominatim policy).
- **Invite tokens:** only a SHA-256 hash is stored; the token travels encrypted in the outbox payload (`tokenEnc`) until the email is sent; single use, expiring, per city; never written to analytics (`redactPath`).
- **KYC:** the GSTIN or enrolment number is stored in `partner_applications.kyc_enc` with a `gstin_index` blind index for duplicate checks; the shop owner is linked once (`owner_user_id`).

## Permission `prices:write` (2026-11-13, Q26)

"Set customer prices per city and PIN code": super_admin, ops_manager and finance. Not catalogue_manager (catalogue texts only) and not city_manager until prices are city-scoped. The price board (`GET /v1/admin/prices/products/{slug}`) needs it too (one permission per area: whoever sees the margins can set them). Writes are compare-and-set on `version` (`STALE_PRICE`) and audited (`price.set` / `price.cleared` with before/after).

## Shop team and money visibility (2026-11-15)

Owner-only routes for the busy toggle and the team check the caller's own `seller_owner` grant for the shop id (404 for any other shop, 403 `OWNER_ONLY` for staff of that shop, 403 for everyone else, 401 anonymous). Staff invites are bound to a phone that is proved by the sign-in code, never by a link, and grant nothing until the invitee accepts them (consent; accept and decline are invitee-only, 404 for any other person or an unverified phone, single use, compare-and-set on the invite version). MechDost staff accounts cannot accept (one person, one side). The owner sees the name they typed, never the account name. Removing a member revokes the role in the same transaction and drops their cached session. `payoutPaise` and the shop's own line prices are returned only for shops where the caller holds `payouts:read` (owners, not staff). Rate limit on invites: 20 an hour per user. Role-leak matrix: `apps/api/test/shop-team.test.ts`.
